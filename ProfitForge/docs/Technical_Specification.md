# Техническое задание — Profit Forge Online

## Контекст

Мобильный игровой продукт привлекает игроков через несколько маркетинговых каналов (Organic, Ads, Referral), монетизируется через разовые покупки и подписки. У команды нет единого инструмента, который бы быстро отвечал на вопрос "что будет с прибылью, если изменить удержание, CAC или маркетинговый микс" — расчёты каждый раз собираются вручную, разными людьми, с риском разъехавшихся цифр.

## Бизнес-вопросы, на которые должна ответить система

1. Какая доля игроков остаётся в продукте по неделям/месяцам после установки (Retention), и в какой момент жизненного цикла когорты происходит наибольший отток?
2. Сколько в среднем приносит один пользователь (ARPU) и один платящий пользователь (ARPPU), и как это соотносится со стоимостью его привлечения (CAC)?
3. Окупается ли продукт при текущей структуре маркетинговых каналов, и через сколько месяцев?
4. Как изменится прибыль при изменении конкретных рычагов — стоимости привлечения, доли платящих, цен на подписки, доли операционных расходов — без необходимости пересчитывать всё вручную?
5. Как будет выглядеть денежный поток на горизонте 1–12 месяцев при текущих трендах, с учётом инфляции OPEX и масштабирования команды?

## Ожидаемый результат

- Модель, которая пересчитывается автоматически при изменении любого входного параметра (не требует ручного пересчёта формул).
- Разделение слоя сырых/исторических данных и слоя сценарного моделирования — изменение сценария не должно портить исторические цифры.
- Возможность сравнить два режима расчёта CAC — по факту (Historical) и по плану (Manual) — на одних и тех же данных.
- Визуализация ключевых метрик (когортный Retention, P&L, KPI) в BI-инструменте, обновляемая без участия разработчика.

## Кому предназначен результат

- Продуктовым менеджерам — для проверки гипотез и планирования акций.
- Финансовым аналитикам — для бюджетирования и прогнозов.
- Основателям — для быстрой оценки здоровья бизнеса.

## Ограничения, заданные на старте

- Данные — синтетические, сгенерированные по заданным распределениям и правилам сезонности (не выгрузка из реальной боевой базы).
- Бизнес-модель упрощена (подробности и обоснование — в `Technical_Documentation.md`, раздел "Ограничения проекта").
- Длительность и глубина сессии не моделируются.
- Прогнозный модуль строится на основе скользящих трендов последнего года, а не на полноценной статистической модели временных рядов.
