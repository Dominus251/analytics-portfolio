# Словарь данных — Profit Forge Online

> Проект хранит данные в двух слоях: сырые CSV (выход генератора, вход ETL) и модель Google Sheets (аналитический слой). Ниже — оба слоя.

## Слой 1. Сырые данные (`data/*.csv`)

### `players.csv` — игроки

| Поле | Тип | Описание |
|---|---|---|
| `player_id` | int | Уникальный идентификатор игрока |
| `install_date` | date | Дата установки приложения |
| `acquisition_channel` | string | Канал привлечения: `Organic`, `Ads`, `Referral` |

### `sessions.csv` — сессии (поведенческая активность)
| Поле | Тип | Описание |
|---|---|---|
| `session_id` | int | Уникальный идентификатор сессии |
| `player_id` | int | Ссылка на `players.player_id` |
| `session_date` | date | Дата входа в игру |

⚠️ Сессии — единственный источник поведенческой активности: `active_players` и `retention_rate` считаются по сессиям.

⚠️ `session_id` — суррогатный ключ без временного смысла: порядок id не обязан совпадать с порядком дат.

⚠️ Генератор связывает транзакции с сессиями: покупка или активная подписка возможны только при наличии входа в этом месяце, поэтому `paying_players` и `active_subscribers` ⊆ `active_players`.

### `purchases.csv` — покупки

| Поле | Тип | Описание |
|---|---|---|
| `player_id` | int | Ссылка на `players.player_id` |
| `purchase_date` | date | Дата совершения покупки |
| `item_category` | string | Категория предмета (например, `consumable`) |
| `base_price` | float | Базовая цена предмета до скидки |
| `discount_pct` | float | Скидка в процентах (0–100) |
| `net_revenue` | float | Фактическая выручка с покупки после скидки |

### `subscriptions.csv` — подписки

| Поле | Тип | Описание |
|---|---|---|
| `player_id` | int | Ссылка на `players.player_id` |
| `plan_type` | string | Тип подписки: `Basic`, `Premium` |
| `start_date` | date | Дата начала подписки |
| `end_date` | date | Дата окончания подписки |
| `monthly_fee` | float | Ежемесячная стоимость подписки |
| `discount_pct` | float | Скидка в процентах (0–100) |

### `marketing_spend.csv` — маркетинговые расходы

| Поле | Тип | Описание |
|---|---|---|
| `month` | date | Месяц (первое число) |
| `channel` | string | Канал: `Organic`, `Ads`, `Referral` |
| `spend` | float | Расходы на канал за месяц |
| `new_installs` | int | Число новых установок за месяц по этому каналу |

⚠️ `Organic` всегда имеет `spend = 0` по определению канала — это не пропуск данных. В `Inputs` есть возможность изменить цену привлечения по этому каналу вручную (параметр CPI по каналам).

## Слой 2. Модель Google Sheets — назначение листов

| Лист | Назначение |
|---|---|
| `marketing_spend` | Неизменяемый источник данных по маркетинговым расходам. Импортируется в первозданном виде после генерации |
| `CohortData` | Неизменяемый источник "сырой правды" — импорт CSV из Python, стабильный фундамент для всех расчётов ниже. |
| `MarketingCAC` | Фактическая стоимость привлечения одного пользователя (CAC) по месяцам. |
| `ChannelMix` | Исторические доли и CPI по каналам — основа для ручного управления CAC. |
| `Inputs` | Единая панель управления всеми рычагами модели (см. таблицу ниже). |
| `Scenario` | Динамическая историческая витрина — пересчитывает прошлое под текущие настройки `Inputs`. |
| `Trends` | Скользящий эталон удержания и ARPU за последний год — база для прогноза. |
| `Forecast` | Операционный прогноз на 1–12 месяцев (игроки, выручка, прибыль). |
| `Dashboard` | Итоговый дашборд с денежным потоком и тепловым форматированием по месяцам. |

### Детализация: колонки `CohortData`

Агрегат, собранный в `prepare_data.py` из четырёх сырых источников (`players`, `sessions`, `purchases`, `subscriptions`) на уровне когорты × месяца жизни.

| Поле | Описание |
|---|---|
| `cohorts_month` | Месяц регистрации когорты (месяц установки, взят из `install_date`) |
| `life_month` | Порядковый номер месяца жизни когорты: 0 — месяц регистрации и т. д. |
| `active_players` | Игроки когорты с хотя бы одной сессией в этом месяце жизни |
| `paying_players` | Игроки с хотя бы одной покупкой или активной подпиской в этом месяце жизни  |
| `active_subscribers` | Игроки с активной подпиской в этом месяце жизни |
| `total_sub_revenue` | Суммарная выручка от подписок когорты за этот месяц жизни |
| `total_purchase_revenue` | Суммарная выручка от разовых покупок когорты за этот месяц жизни |
| `total_items_bought` | Суммарное количество купленных предметов за этот месяц жизни |
| `cohort_size` | Размер когорты — число уникальных игроков на месяце жизни 0 |
| `retention_rate` | `active_players / cohort_size` — сессионное удержание: доля когорты, вернувшаяся в игру к этому месяцу жизни. На life_month 0 = 100% по определению (установка = первая сессия) |

⚠️ `paying_players` и `active_subscribers` могут пересекаться
(подписчик с покупкой); оба — подмножество `active_players`.

### Производные метрики (`Scenario`, `Dashboard`)

| Поле | Описание |
|---|---|
| `monthly_revenue` | `total_sub_revenue + total_purchase_revenue` за месяц (месячная выручка) |
| `total_cohort_revenue` | Комулятивная сумма по всем месяцам жизни когорты |
| `arpy` | `total_revenue / cohort_size` — ARPU |
| `arppy` | `total_revenue / paying_players` — ARPPU по платящим; числитель — вся выручка когорты  |
| `arppy_sub` | `sub_revenue / active_subscribers` — подписочный ARPPU |
| `cumulative_ltv` | Накопительная сумма `arpy` по месяцам жизни |
| `romi` | `cumulative_ltv / cac` |
| `payback_flag` | TRUE с месяца, когда кумулятивная выручка когорты покрывает кумулятивные затраты (маркетинг + OPEX при `Include OPEX in Payback? = TRUE`) |
| `profit` | `total_cohort_revenue − total_cohort_cost` |


### Параметры панели управления (`Inputs`)

| Параметр | Описание |
|---|---|
| Retention Boost | Множитель удержания |
| Revenue Multiplier | Множитель выручки |
| Items Multiplier | Множитель покупок |
| Cohort Size Multiplier | Множитель размера когорт |
| CAC Multiplier | Множитель CAC |
| Monthly OPEX | Ежемесячные операционные расходы |
| Include OPEX in Payback? | Учитывать ли операционные расходы при подсчёте флага окупаемости |
| CAC Mode | Historical — расчёт опираясь на исторические параметры / Manual — расчёт из параметров пользователя |
| Manual Mix Mode | Historical Mix* / Manual Mix* |
| Organic / Ads / Referral Share | Доли каналов - 100% максимум регулируются автоматически |
| CPI по каналам | Стоимость установки |
| Forecast Months | Количество месяцев прогноза 1-12 |
| Opex Inflation Rate | Инфляция OPEX |
| Team Scaling Factor | Масштабирование штата |
| New Players per Month | Новые игроки в месяц |
| Planned CAC | Плановый CAC |
| Paying Share | Доля платящих |
| Premium Share | Доля премиум-подписок |
| Subscription Prices | Цены Basic / Premium |

⚠️ Изменение любого параметра в `Inputs` вызывает автоматический пересчёт всей модели ниже по цепочке (`Scenario` → `Trends` → `Forecast` → `Dashboard`).
